## Procesos críticos a conservar

| Flujo | Dependencias que deben permanecer unidas | Riesgo en destino |
|---|---|---|
| Alta/edición de bien | Validación servidor → permiso/MFA → versión/clave → bien + comando + auditoría + outbox | Catálogos no reemplazan código único ni semántica de PATCH completo |
| Asignación/traspaso/devolución | Bien/funcionario vigentes → origen esperado → locks/versión → historia + cierre/apertura + auditoría + aviso | DATE y auto-FK aisladas no conservan atomicidad, precisión ni vigente única |
| Cambio de unidad | Pertenencia actual + snapshot histórico; conserva custodia | No debe crear movimiento de custodio ficticio ni reescribir unidad histórica |
| Malo/baja/reactivación | Condición, custodia y situación independientes; baja bloqueada con custodia | EN PROCESO DE BAJA no representa baja concluida |
| Cuenta/rol/desactivación | MFA, propio rol y último administrador; versión autorización/revocación antes de próxima petición | BIT activo/perfiles N:M no reproducen estado pendiente ni permisos por sí solos |
| Exportación | Selección REPEATABLE READ → instantánea durable → hilo render → reautorización → descarga propia/TTL | Jobs no aparecen en las 30 tablas; conteos, filtros y privacidad deben sobrevivir |
| Avisos | Commit empresarial → outbox destino fijo → worker/token/lease → resultado durable | Fallo de envío no revierte negocio; incierto no se reenvía a ciegas |

## Permisos y contratos que condicionan el mapeo

Las ocho capacidades actuales son inventario.consultar, historial.consultar, reportes.exportar, inventario.modificar, cuentas.administrar, configuracion.administrar, auditoria.consultar y auditoria.exportar. Administrador activo con MFA opera sujeto a reglas; lectura solo las tres primeras. Inventario es compartido: no se inventa restricción por propietario/unidad. Propiedad del trabajo de exportación sí se valida.

Conservar cookie opaca y tokens solo en servidor, Origin/CSRF, principal vigente y contexto por transacción, revocación, consultas parametrizadas, no-store y errores saneados. Idempotency-Key/If-Match se exigen según endpoint: login/enlace/recuperación no tienen el mismo contrato que comandos de negocio. El alta/edición original de bienes exige motivo pero no el flag confirmado usado en procesos/panel; no se uniforma silenciosamente.

OpenAPI de Fase 7 describe una superficie histórica parcial. La línea base actual se obtiene de rutas ejecutables y documentación incremental; no se declara OpenAPI completo ni se reescribe ahora. Las referencias de API y listas de tipos se conservan o versionan explícitamente en Fase 3.
